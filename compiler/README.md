# QuarkLang · compiler

**English** · [简体中文](README.zh-CN.md)

**Cross-platform compiler branch**. Backend: **LLVM IR** (no C transpilation) — `qkc` emits textual LLVM IR and `clang` produces native code for any LLVM-supported platform.

## Architecture: a single syntax source

The compiler no longer carries its own lexer/parser; the one and only front-end entry point is the language implementation (`internal/lang`, shared with the interpreter):

```
lang.CompileWithImports(src, filename)   // lexing/parsing/type checking + recursive import merging
  → internal/cgen/lower.go               // canonical AST → cgen IR (unsupported constructs are errors)
  → internal/cgen/cgen.go                // cgen IR → LLVM IR (emitter)
```

- `cgen.Transpile(src, filename)`: filename determines the same-directory search scope for `import` and is used for diagnostic positions.
- Macro expansion still goes through the interpreter's token-level macro system (`compiler/macros.go`, compile mode) and is then handed to the language front end.
- The former home-grown cgen parser has been deleted: there is only the one canonical syntax (type-first).

## Usage

~~~sh
go run . testdata/hello.qk          # emit LLVM IR to stdout
go run . -run testdata/hello.qk     # clang-compile the IR into a native binary and run it
go run . -run testdata/demo.qk      # import + recursion + List + try/catch example
go test ./...                       # unit tests (llvm-as syntax check + lli end-to-end)
testdata/compare.sh                 # interpreter vs compiler byte-for-byte comparison (all corpora)
~~~

## Supported subset (semantic baseline = the interpreter)

**The same source is byte-identical under `quark` (interpreter) and `qkc -run` (compiler)**;
`testdata/compare.sh` compares in bulk, and `testdata/cases/*.kq` (+ `cases_run/`, which needs clang linking)
are the regression corpora, whose baseline output is generated by the interpreter.

- Entry point: `fn main(IOStream io) { ... }` (required, first parameter is IOStream); `import` is merged recursively
- **Parameter semantics (canonical)**: formal parameters are always **passed by reference** (at the LLVM level a formal parameter = value type\*, so callee reads and writes reach the caller);
  an lvalue argument uses its own storage, a non-lvalue argument is a caller temporary cell; a `copyd` formal parameter is deep-copied at entry (scalar/String copied,
  struct copied recursively, List<int> buffer copied) and writes by the callee are not written back; the `self` receiver is bound by value (same as the interpreter)
- Functions: any scalar/struct/interface return and formal parameter (int/bool/float/String/struct/interface); calls/recursion/tail calls
  (tail calls are emitted only when argument addresses are stable, avoiding dangling pointers)
- Variables and statements: int/bool/float/String/List<int>/struct/interface/thread/Channel/memorize;
  assignment, `l[i] = v`, struct field assignment, `if/else`, `while`, C-style `for`, iterating `for (T x : l)`,
  `break`, `log`, `try/catch (void e)`, `return`, `delete l`, `io.println/io.print`
- Expressions: int/float/bool/String/List literals (in any expression position), `+ - * / % << >>`,
  comparisons (int/float/String/bool), short-circuit `&& || !`, String concatenation, `int/float/bool.toString()`,
  `l.size()/get(i)/append(v)/l[i]` (the receiver may be a variable or a struct field), built-in `sum(...)`/`clock()`
- Object model: struct (reference semantics, identical to the interpreter's *Struct aliasing), struct literals (named + positional),
  `impl` instance/static methods, `space` (`space::f`), Operation operator overloading (`__add__` etc.)
- Generics: `fn<T>` and `type struct<T>` / `impl<T>` are monomorphized per call site; a generic function can serve as a `sum` generator
- Interfaces: structural satisfaction (checked by internal/lang Typecheck) + vtable/thunk dynamic dispatch;
  **anonymous struct / anonymous interface type annotations** (the parser synthesizes `__anon_struct_N`/`__anon_iface_N`,
  and the compiler lowers under the synthesized real name); **receiver recognition is by type** (the first parameter's type is `Self` or its base name equals the impl/interface type,
  regardless of the formal parameter name; both `fn sum(P me)` and `fn sum2(Self other)` are instance methods)
- `interface{}` (tAny): boxing any scalar/String/List<int>/struct + a runtime type descriptor
  (`%RT = { str, name, kind }`, `@rt$<T>` constants; scalars are boxed into a heap cell, List/struct use the object pointer);
  `io.println` dispatches printing by kind (struct in declared field order, nil → `nil`), `==`/`!=` go through
  `ql_any_eq` (int/float compared numerically across types, String by content, List/struct by reference, nil==nil),
  and unboxing to int/float/bool/String checks kind at runtime
- Signature calls: `f(args) @mb()` (built-in **memorize**: memoized by the int argument list, runtime
  `ql_memo_new/get/put`; explicit prefix arguments at @ are evaluated and discarded — same as the interpreter)
- library FFI: LLVM `declare` + direct C-ABI calls; the `; qkc-link: -lm` marker in the IR is turned into link arguments by qkc
- taskm: `spawn/merge/block/done/channel` against the `qthreads.c` runtime (pid = small integer handle);
  `merge`/`t.merge` supports 0..4 arguments (int/bool/float/String/struct/List/pointer etc., via 4 i64 slots)

## Not yet supported (must be a clear error, never a silent miscompile)

Every construct the backend does not lower returns a hard `compiler: not supported yet …` diagnostic together with a source position:

- `List<T>` (T ≠ int) variables/formal parameters/returns (e.g. `String.split` needs List<String>), HashTable
- `interface{}` unboxing to struct/List, boxing `pointer`/`long`, `interface{}` as a merge/FFI argument
- printing a multi-field struct inside `interface{}`: the interpreter's field order comes from a Go map (**itself nondeterministic**),
  while the compiler prints in declaration order — identical on single-field sources, multi-field cannot be aligned byte for byte
- user-defined Sign instances (`f(args) @sign` only lowers the built-in memorize), `copyd` interface formal parameters/interface fields
- pointer types `T&`/`pointer T`, `new T[n]`, `Copyd<T>` type annotations (`copyd` as a **modifier** is already supported)
- printing struct/interface/memorize values (the interpreter's struct field order comes from a Go map and is itself nondeterministic)
- `merge` with more than 4 arguments, `String.split`/`List<String>`-related built-ins
- library FFI already supports `long`/`pointer` linking; float modulo ends in a runtime error on both paths (identical wording)
- a function containing `log` whose return value is used by an expression (the interpreter returns nil, which the static type cannot express)
- `merge` with multiple/non-int arguments (the qthreads runtime carries only 1 int), `thread.talk`

## Layout

- `main.go` —— `qkc` CLI (reads .qk, emits LLVM IR; `-run` compiles and runs; parses `; qkc-link` link markers)
- `macros.go` —— reuses the interpreter's token-level macro system (compile mode)
- `qthreads.c.txt` —— taskm runtime (embedded; thread pool + channels, pid is a small integer handle)
- `internal/cgen/lower.go` —— the lowering layer from canonical AST → cgen IR plus all support diagnostics
- `internal/cgen/lower_generic.go` —— generic monomorphization (fn<T> / struct<T> / impl<T>)
- `internal/cgen/lower_iface.go` —— interface vtable + thunk dynamic dispatch
- `internal/cgen/lower_taskm.go` —— taskm thread/channel lowering
- `internal/cgen/cgen.go` —— LLVM IR emitter (types/string constants/printf/SSA values/function attributes/vtable)
- `testdata/cases/` `testdata/cases_run/` —— interpreter/compiler output comparison corpora (`.out` is the interpreter baseline)
- Regenerate the `.out` baselines with the interpreter from this directory (they are not committed):
  `for f in testdata/cases/*.kq; do ../quark "$f" > "${f%.kq}.out"; done`
- `testdata/compare.sh` —— bulk byte-for-byte comparison (interpreter vs `qkc -run`)

For the language design see `SYNTAX.md` (the canonical syntax list, kept in sync with the implementation).
