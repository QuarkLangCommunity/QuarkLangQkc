# Performance claims inventory

This document inventories every quantitative performance claim in `README.md`, the documentation
under `docs/`, and the standard, and states for each one where it came from and whether any checked-in
harness produces it. It is the input to the rule that a performance number must be generated from a
record, not typed by hand.

Status legend:

- **generated** — a checked-in harness writes a record, the generator renders the block, and a test
  fails when a quoted copy and the record disagree.
- **harness, no record** — a script can produce a similar measurement, but it writes nothing, applies
  no load gate, records no spread or checksum, and no test compares it with prose.
- **manual** — the number exists only where it is quoted; nothing in the repository can reproduce it.
- **historical** — a one-off observation of a revision that no longer exists; kept as history, not as a
  claim about the current build.

The tide block is the one performance claim family that already satisfies the rule: `bench/tide/run.sh`
writes `spec/bench/tide.tsv` behind a load gate and a canonical-shape guard, `internal/benchgen` renders
`docs/tide-benchmark.md`, and `TestTideClaimsMatchMeasurement` compares the copies in `README.md` and
`spec/STANDARD.md` §10 with the record. Everything below the tide block in this inventory is a
remaining manual claim.

## Why this matters

Three of the README claims are wrong or unsupportable as written:

1. R-02/R-09/R-10 mix different source programs. `bench/qk/fib.qk` computes `fib(30)`, while the C,
   Rust, Go and Erlang sources compute `fib(35)`, and `bench/Makefile` compiles `examples/fib.qk` for
   the QuarkLang target. The quoted "fib(35) 21 ms (C: 22 ms)" therefore does not correspond to any
   one checked-in command.
2. R-12 labels two values per language as "P99" without saying what the pair is, and no source exists.
   It cannot be reproduced as stated.
3. R-17's "Before" column refers to binaries that are not in the tree; the numbers are history, not a
   statement about the current build.

## Disposition

The rule is one sentence: a number a reader can act on must come from a record, and every other number
must stop looking like one.

- **Automate** (checked-in workload, comparison controls where the claim compares, load gate, canonical
  shape, record, generated block, drift/claim test): the cross-language fib family (R-02, R-05, R-09,
  R-10), the closed-form `sum` (R-06, R-13), the latency claim (R-03, R-12), and the interpreter versus
  native table (R-15, R-16). The same harness and generator as the tide block are extended, not
  duplicated.
- **Withdraw or mark historical** (no checked-in producer, and the measurement cannot be repeated on
  this tree): R-07, R-08, R-11, R-17 through R-25, D-03 through D-10, and the retrospective parts of
  D-01/D-02. Numbers that a reader could mistake for a current measurement are removed from the live
  text or explicitly labelled as a historical observation of an earlier revision.
- **Keep generated**: R-14, D-11, S-01.
- **Leave excluded**: S-03 and D-12 through D-14, which are correctness/status facts, not performance
  claims.

The standard's revision log records the earlier figures and why they moved, including any claim that
had to be withdrawn because it could not be put under the machinery.
